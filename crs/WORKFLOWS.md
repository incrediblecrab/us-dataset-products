# workflows

**Objective:** keep the three datasets current with no personal device and no person, given a commit every 60 days. Each pipeline is scheduled daily at 12:37 UTC. Minute 37 avoids the start of the hour, which GitHub names as a busy time. GitHub starts scheduled runs late and sometimes [drops them](https://huggingface.co/datasets/incrediblecrab/us-crs-research-papers#how-it-stays-current). From November 9 to 22, 2026 it started this repository's daily runs 5.8 to 10.1 hours after 12:37 UTC.

**Schedule history:** on October 12, 2026 the owner asked for one daily update. From September 27 to October 15, 2026 GitHub started every one of the 208 scheduled runs of the four dataset pipelines in this account late, by 2.4 to 9.2 hours, and the 18 daily runs scheduled at 14:00 UTC from October 13 by 3.9 to 6.2 hours. The daily cron was moved to 12:37 UTC to target a start near 17:00 UTC (12:00 EST, 13:00 EDT). On November 23, 2026 the owner asked for a run every 6 hours; from then to November 27 GitHub started 9 of the 19 scheduled runs of each pipeline. On November 27, 2026 the owner asked for a run every 12 hours. On November 28, 2026 the owner asked for one daily update again, at 12:37 UTC.

**Inputs:** the secret `DATA_GOV_API_KEY`, and each job's OIDC token, which Hugging Face exchanges for a short-lived write token when the dataset lists this repository and workflow as a Trusted Publisher; otherwise the run fails.

**Files:**

- [`crs-pipeline.yml`](../.github/workflows/crs-pipeline.yml), products: `probe` makes one API request. When needed, `run` syncs; `verify --live` and `squash` follow a commit. `continue` starts the next run when one ran out of budget mid-fetch. `inactivity` fails after 50 days without a commit, before GitHub disables every schedule here at 60. It makes no keepalive commit: GitHub [called](https://github.com/ddev/github-action-add-on-test/issues/46) that a Terms violation.
- [`crs-summaries.yml`](../.github/workflows/crs-summaries.yml), bill summaries: `run`, then `verify` and `squash` after a commit; `continue` as above.
- [`crs-constitution.yml`](../.github/workflows/crs-constitution.yml), Constitution Annotated: `run`, then `verify --live` and `squash` after a commit.
- [`crs-test.yml`](../.github/workflows/crs-test.yml): runs the test suite on pushes to `main` and pull requests that change `crs/` or this workflow, with read-only contents and no OIDC token, so it cannot publish.

GitHub reports a failed scheduled run to whoever last changed its cron, by email if their settings allow. Every Hugging Face call (reads, the Trusted Publishing token trade, commits, squashes) is retried after 1, 2 and 3 minutes on a 408, 429, 5xx or dropped connection. A run stopped because Congress.gov or GovInfo stayed unreachable through every retry keeps what it committed and passes with a warning while a run has finished in the last 72 hours (`OUTAGE_GRACE_HOURS` in `crs_products/cli.py`), and fails once none has, so a lasting outage still sends the email. `verify --live` that cannot reach the source reports a warning and lets the checks against the manifest decide, since the step runs after every commit, an outage-stopped run's record included. A dispatch with `args` runs only a bounded test. The root's `.github/` has no README, which GitHub would show instead of the repository's.
