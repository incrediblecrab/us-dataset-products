# workflows

**Objective:** keep the Hugging Face dataset current with no personal device and no stored Hugging Face token. The workflow is scheduled daily at 12:37 UTC. Minute 37 avoids the start of the hour, which [GitHub documents as a busy time](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). GitHub starts scheduled runs late and sometimes drops them.

**Schedule history:** On October 12, 2026, the owner asked for one daily update. From September 27 to October 15, 2026, GitHub started all 208 scheduled runs of the four dataset pipelines in this account 2.4 to 9.2 hours late; the 18 daily runs scheduled at 14:00 UTC from October 13 started 3.9 to 6.2 hours late. The daily cron was moved to 12:37 UTC to target a start about four hours later, near 17:00 UTC (12:00 EST, 13:00 EDT). From November 9 to 22, 2026, GitHub started this repository's daily runs 5.8 to 10.1 hours after 12:37 UTC. On November 23, 2026, the owner asked for a run every 6 hours; from then to November 27, GitHub started 9 of the 19 scheduled runs of each pipeline. On November 27, 2026, the owner asked for a run every 12 hours. On November 28, 2026, the owner asked for one daily update again, at 12:37 UTC.

**Freshness:** When the probe finds neither source nor card changes, the run writes nothing to the dataset, not even a timestamp or run record. The repository health check tracks freshness from GitHub Actions workflow runs, not dataset commits. The card dates are source reading times.

**Inputs:** GitHub's OIDC token, which Hugging Face exchanges for a one-hour dataset-scoped write token when the Hub dataset has this repository, branch and `local-laws-pipeline.yml` registered as a Trusted Publisher. No `HF_TOKEN` secret is used.

**Files:**

- [`local-laws-pipeline.yml`](../.github/workflows/local-laws-pipeline.yml): `probe` compares New York filing-year counts, FEMA file hashes and the published card with cheap reads. When only the card render changed, `card` updates it without a full build; otherwise `run` harvests New York and FEMA, builds from pinned sources, writes only if changed, verifies the published commit, then checks pinned sources for newer releases a person must review. If fema.gov refuses a GitHub-hosted runner, as it returned HTTP 403 on September 27, 2026, the run logs a warning with the error and builds the FEMA table from the FEMA files the last build stored in the dataset, once they match the manifest, so New York updates still publish; with no stored files it writes no commit. `inactivity` fails after 50 days without a commit; it makes no keepalive commit because GitHub treats that as circumventing the 60-day schedule disablement policy. The root's `.github/` has no README, which GitHub would show instead of the repository's.
- [`local-laws-test.yml`](../.github/workflows/local-laws-test.yml): runs the test suite on pushes to `main` and pull requests that change `local-laws/` or this workflow, with read-only contents and no OIDC token, so it cannot publish.

**Pin reviews:** `check-pins` exits 0 for current pins, 3 for a newer LOCUS or BIA release, and 1 if the check cannot finish. On exit 3, the `sync` job opens one GitHub issue per release or reuses the open issue with the same title. The run passes with a warning linking to each issue; it fails if the check cannot finish or an issue cannot be looked up or filed. Close the issue after updating the pin.
